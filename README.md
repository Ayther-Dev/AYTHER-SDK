# AYTHER SDK

> **Status:** Experimental / Developer Preview  
> **Notice:** Public APIs, ABI, and contracts are under active development and subject to breaking changes prior to version 1.0.

**AYTHER SDK** is the open suite of contracts, APIs, CLI tooling, examples, and conformance tests used to integrate with **AYTHER Engine**. It allows developers to create, inspect, sign, and validate asset packs (`.ay`) independently, without relying on proprietary authoring environments such as AYTHER Lab.

### What is AYTHER?
AYTHER remasters the audiovisual layer of classic 2D retro games in real time while preserving the original game logic and execution unchanged. It intercepts sprites, tile planes, and audio events generated by an emulation core and dynamically replaces them with high-fidelity assets packaged into standalone `.ay` containers.

## Target Audience

* **Emulator & Frontend Developers:** Integrate real-time remastering sessions into runtimes, frontends, launchers, and native applications.
* **Pipeline & Tooling Creators:** Build custom inspection tools, automated packaging workflows, and asset pipelines without proprietary intermediaries.
* **Technical Pack Authors:** Create, sign, and verify `.ay` packs using scriptable CLI-driven workflows.
* **Preservationists & Homebrew Developers:** Document, test, and ensure open interoperability on legacy hardware architectures.
* **Studios & Publishers:** Technically evaluate real-time remastering capabilities for legacy IP and retro catalog enhancements.

## Capabilities

### What You Can Build Today
* **Session Lifecycle Integration:** Control AYTHER Engine lifecycle events natively from C/C++ host applications.
* **Hardware Observability:** Inspect sprite tables, plane tiles, and audio events in real time through the observable ABI.
* **Bit-Exact Content Identity:** Generate deterministic, bit-exact hashes and identities for graphical and audio patterns.
* **`.ay` Pack Management:** Build, validate, sign, verify, and inspect `.ay` package containers.
* **Sandboxed Scripting:** Author game-specific behaviors using Lua scripts running inside AYTHER’s secure sandbox.
* **Conformance Testing:** Validate custom tooling and engine integrations against public specifications and synthetic fixtures.

### Out of Scope
* **Distribution of ROMs, BIOS, or Cores:** The SDK does not supply copyrighted game assets, system software, or emulator cores.
* **Pre-1.0 ABI/API Stability Guarantees:** Binary and source compatibility are not guaranteed before release 1.0.
* **UI Replacement:** The SDK provides headless/CLI tools; it does not replace the visual timeline and live editing suite of AYTHER Lab.
* **Commercial Extensions:** Proprietary or studio-grade extensions are licensed separately and fall outside the public SDK scope.

## Workflow (Open Authoring Pipeline)

The SDK enables fully scriptable pack creation without requiring commercial GUI tools:

```text
  ┌───────────────────────┐
  │ Local ROM + Local Core│
  └───────────┬───────────┘
              ▼
  ┌───────────────────────┐
  │  Observation / Capture│
  │         Tool          │
  └───────────┬───────────┘
              ▼
  ┌───────────────────────┐
  │    observed_*.toml    │ ◄─── Remastered assets (PNG, WAV, etc.)
  └───────────┬───────────┘
              ▼
  ┌───────────────────────┐
  │   Pack Build Tool     │ ◄─── Injection rules, metadata, Lua scripts
  └───────────┬───────────┘
              ▼
  ┌───────────────────────┐
  │  Validation & Signing │
  └───────────┬───────────┘
              ▼
          .ay Pack
```

> **Note:** Fixtures, examples, and test suites provided with this SDK **must never** contain copyrighted commercial ROMs. Use synthetic fixtures, public domain samples, or homebrew ROMs only.

## Legal Principles: BYOR and BYOC

AYTHER enforces clear technical and legal boundaries between engine code, assets, and game data:

* **BYOR (Bring Your Own ROM):** AYTHER does not host, distribute, or bundle ROMs, BIOS files, or copyrighted game code. Packs (`.ay`) contain only asset replacements, configuration metadata, and script rules. Users must provide their own legitimately acquired game copies.
* **BYOC (Bring Your Own Core):** The SDK does not distribute third-party emulator cores (such as libretro cores). Integrators and users must supply compatible cores and comply with their respective upstream licenses (e.g., GPL, MIT).

> *BYOR and BYOC delineate technical boundaries. Developers, pack authors, and integrators remain solely responsible for securing all necessary intellectual property rights for any assets, code, trademarks, or audio used.*

## Security

All `.ay` packages, external scripts, and user-supplied cores must be treated as **untrusted input**.

The SDK enforces the following defensive principles:
* Strict validation of container paths (preventing *Directory Traversal* vulnerabilities).
* Hard decompression limits and quota enforcement (mitigating *Zip Bomb* attacks).
* Cryptographic signature and manifest verification prior to asset loading.
* Hermetic Lua sandboxing (no unmanaged file system access, network sockets, or external process execution).
